# 网页翻译助手

一个**不依赖浏览器内置翻译**的整页翻译扩展。浏览器自带翻译提示「无法翻译此页面」时，它仍然能把页面翻译出来。

---

## 为什么它能解决「无法翻译此页面」

浏览器（Chrome / Edge）的内置翻译是一条**单点链路**：页面 → 浏览器翻译引擎 → Google 翻译服务。这条链上任何一环出问题，你看到的就只有「无法翻译此页面」：

| 原因 | 内置翻译的表现 | 本扩展怎么处理 |
| --- | --- | --- |
| 翻译服务连不上（网络受限） | 直接失败，无备选 | 内置 4 个引擎，自动探测、失败降级 |
| 页面没声明 `lang`，语言判断失败 | 不弹翻译或翻译失败 | 自己判断文本语言，不依赖页面标记 |
| 内容在 iframe / Shadow DOM 里 | 抓不到 | 注入所有 frame，递归遍历 Shadow DOM |
| 内容异步加载（无限滚动、SPA） | 只翻首屏 | 监听 DOM 变化，新内容增量翻译 |

核心区别：**它不用浏览器的翻译引擎**。扩展自己遍历页面上的文本节点，把译文直接写回 DOM，所以内置翻译坏了它也能工作。

---

## 安装

1. 打开 `chrome://extensions`（Edge 是 `edge://extensions`）
2. 打开右上角的 **开发者模式**
3. 点 **加载已解压的扩展程序**，选择本文件夹
4. 装好后建议在扩展详情里打开「固定到工具栏」

> 首次使用时，扩展会自动探测哪个翻译引擎能连通，选最快的那个，并缓存 30 分钟。

---

## 使用

| 方式 | 操作 |
| --- | --- |
| 工具栏图标 | 点开 → 「翻译此页」 |
| 页面悬浮球 | 右下角蓝色圆球，点一下翻译，再点还原 |
| 快捷键 | 网页里按 `Alt + T` 翻译 / 还原 |
| 右键菜单 | 「翻译此页面」/「翻译选中内容」 |

> **关于快捷键**：扩展在页面里自己监听了一次按键，所以 `Alt + T` 开箱即用，不依赖浏览器分配。
> 如果你想让它在地址栏、新标签页里也生效，需要到 `chrome://extensions/shortcuts`
> （Edge 是 `edge://extensions/shortcuts`）手动分配一次 —— 通过「加载已解压」安装的扩展，
> 浏览器**不会自动采纳** manifest 里的建议快捷键。设置页有「设置快捷键」按钮可直接跳过去。

两种显示方式：

- **替换原文**：直接把页面文字换成译文，排版最干净
- **双语对照**：原文保留，译文以蓝色插在下面，适合对照阅读

## 翻译引擎

| 引擎 | 说明 |
| --- | --- |
| **腾讯翻译君** | 国内直连，支持批量（一次 40 段），速度最快，默认首选 |
| **有道翻译** | 国内直连，单条请求（部分文本会返回空，已做质量校验） |
| **MyMemory** | 免费兜底，有每日配额 |
| **Google 翻译** | 译文质量最好，但国内基本连不通，所以排在候选最后 |
| **自定义 API** | 任何 OpenAI 兼容接口（DeepSeek、通义、各类中转都行），译文质量可控 |

选「自动选择」时，扩展按上面的优先级顺序探测，用第一个可用的引擎。
**探测失败不会中断翻译**——会直接逐个引擎真刀真枪试一遍，避免一次网络抖动就让整个功能不可用。

如果四个内置引擎都不通，在设置里配一个自定义 API 即可——填接口地址、Key、模型名三样。

---

## 关于中文页面

扩展会跳过**已经是目标语言**的文本。中英混排（如「群晖 DSM 教程」）按中文处理，
不会送去翻译——否则引擎可能把「群晖」改写成别的字。

所以在一个中文页面上点翻译，只有英文部分会被翻（比如侧边栏的 `Chat` → 「聊天」），
中文正文保持原样。

## 设置项

- **目标语言**：19 种常用语言
- **显示方式**：替换 / 双语
- **打开网页后自动翻译**：默认关闭
- **页面悬浮球**：可关掉
- **排除的网站**：每行一个域名，这些站点不会自动翻译（手动点击仍可翻）
- **测试全部**：一键测出每个引擎的延迟和可用性，方便判断问题出在哪

## 常见问题

**Q：翻译很慢或只翻了首屏？**
先翻视口内的内容，剩余部分在后台继续，滚动时会陆续出现译文。大页面首屏通常 1～2 秒。

**Q：某些文字没被翻译？**
以下内容会被有意跳过：代码块、输入框、可编辑区域、纯数字/符号、以及已经是目标语言的文本。另外 `translate="no"` 的元素也会跳过。

**Q：翻译后页面排版乱了？**
换用「替换原文」模式通常更稳；双语模式会在段落里插入元素，个别布局敏感的站点可能受影响。

**Q：能翻 PDF 吗？**
不能。PDF 的文字在浏览器的 PDF 阅读器里，扩展无法注入。这类页面请用其他方式。

**Q：能翻 Google Docs 这类画布渲染的页面吗？**
不能。文字画在 canvas 上，DOM 里没有可替换的文本节点。

**Q：会不会把我浏览的内容发出去？**
翻译请求只发送页面上的**文本片段**到所选翻译引擎，不发送 URL、Cookie 或页面结构。所有设置和缓存都在本地，没有账号、没有服务端。

```
└── icons/               图标
```

## 已知限制

- 浏览器内部页面（`chrome://`、扩展商店）无法注入脚本，不支持翻译
- PDF、canvas 渲染的内容（Google Docs、部分阅读器）翻不了
- 双语模式在布局极度敏感的站点上可能轻微影响排版
- 依赖第三方免费接口，接口若变更需相应调整（可在设置里切换到自定义 API 兜底）
